# gdl-cgroup

The figures every gdl segment and hub serves about its own process: prometheus's process collector (`process_cpu_seconds_total`, `process_resident_memory_bytes`, and the rest), and `process_cgroup_*`, read from the process's own cgroup v2 files (`cpu.stat`, `cpu.max`, `memory.current`, `memory.peak`), which it finds through `/proc/self/cgroup`. A process under a CPU limit reads at most its limit in CPU seconds, so its real need is its cgroup's CPU use (`process_cgroup_cpu_usage_seconds_total`, to the microsecond) plus its throttled time. The files are read only when `/metrics` is scraped, so nothing runs on the request path, and a file that is missing or unreadable (cgroup v1, not Linux) leaves its metric out rather than failing the scrape. See `docs/src/operations/observability.md`.
