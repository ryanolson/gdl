# The `dir` directory backend: review round 1

Reviewer: an independent reviewer, read-only, with the `thermo-nuclear-code-quality-review` and `rust-code-review` skills, in `/tmp` copies with their own target directories (2026-10-22). Target: `7ad806d..d8459c0`: `DirectoryBackend::Dir` with its path in a cell's settings (`73e95c5`), and `DirDirectory`, one JSON file per cell written by a temporary file and a rename and polled every 50 ms by one task per watched class, with its conformance run and tests (`d8459c0`). The reviewer ran fmt, clippy, the `gdl-cells`, `gdl-model`, and runtime settings tests, and the workspace suite. Verdict: APPROVE-WITH-CHANGES, one major and two minor findings.

| # | Severity | Finding | Ruling | Evidence | Change |
|---|---|---|---|---|---|
| 1 | major | The poller trusted an unchanged length and an old enough modification time as proof that a file had not changed, so a replacement with the same length and a restored time was never seen | partially valid: a write the backend makes always has a later time, so only something that sets the old time back (`cp -p`, `rsync -t`, a restore) hits it, but then the cache never recovers | `a_rewrite_that_restores_the_files_time_is_seen`: no put of seq 2 within 5 s | on unix the stamp also holds the inode and the change time, which a rename and every write move and nothing can set back; the settle rule counts from the change time, as a pure function with its own test (`de458a1`) |
| 2 | minor | A record that stopped parsing or was deleted while its class was unwatched did not invalidate an earlier resume token | valid: the contract says a token from before an unwatched spell in which the files changed yields `Resnapshot` | `a_record_lost_while_unwatched_refuses_the_token` (bad file, deleted file) resumed with `Synced` | the first scan after an unwatched spell counts a lost record as a change; a record lost while watched still emits nothing, and `LIMITATIONS.md` says so (`7468bdc`) |
| 3 | minor | A cell's file the backend could not read was treated as absent, contrary to the documented `DirectoryError::Unavailable` | valid: an unreadable file is an operational fault, unlike one that does not parse | `a_file_it_cannot_read_is_an_error` (mode 000) gave an empty snapshot | a scan error other than a missing file ends every watch of the class with `Unavailable` (`6a7ed6d`) |
