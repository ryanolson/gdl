# Hosted frontends, hub deployment, and the composer's dialogs: mega review pass 1

Scope: the work merged into `main` on 2026-10-20 as `c7589e4` (the public gdl history: hosted source nodes, multi-root graphs, node configuration, the discovery hub, Compose deployment, request routers, Git sources, and the composer's placement, import, and Deploy dialogs), reviewed as the uncommitted tree before that merge.

Reviewer: a fresh Opus subagent, read-only, running the thermo-nuclear code-quality review. It ran the workspace suite, clippy with all features, fmt, `generate --check` for both examples, the hub test by hand, the example workspaces, and the Node editor tests, and reproduced five findings by probe (a built binary, a started server, a scratch graph). A `phone-a-friend` pass ran on the generator and shutdown surfaces and independently reported M2, M3, the M1 collision, S4, and S5. Verdict: REJECT, 5 must fix, 8 should fix, 5 documentation.

Before the pass, the orchestrator made the suite green on this macOS host: blessed two trybuild `.stderr` files whose only change was rustc writing `std::option::Option` and `std::string::String` (new dependencies made the short names ambiguous), regenerated the stale `examples/chat` and `examples/asr` segments, canonicalized the temporary directory in the export test (cargo prints `/private/var`, the test built `/var`), and restored the compose test's expectation once the `hub` feature became conditional (row S1).

During the pass the owner ruled, in conversation: instance counts per segment are dynamic under a hub; a segment should be live before it is ready; readiness is a signal each node gives, each segment gives to the hub once its nodes have, and each segment waits for from at least `min_replicas` instances of every segment. Rows S1, S4, and S5 are fixed to those rulings rather than to the reviewer's remedies.
