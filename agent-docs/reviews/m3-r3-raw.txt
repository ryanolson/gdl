1. **P1 — `Open` sends still bypass deadline enforcement.** [crates/gdl/src/dist/hop.rs:494](/home/ryan/repos/dynamo-gdl/crates/gdl/src/dist/hop.rs:494), also line 587. While generation is pending, velo heartbeats can fill the bounded sender queue if the consumer or transport stalls. Sending `Open` then waits without polling the request deadline or forwarding stop, retaining the task, admission share, and egress permit. This leaves the first review’s blocked-send fix incomplete. **Change wanted:** use interruption-aware delivery for `Open` too; test retirement at the producer’s deadline before downstream cancellation can rescue it.

2. **P1 — Entry admission and forward egress waits can outlive the deadline.** [crates/gdl/src/dist/hop.rs:354](/home/ryan/repos/dynamo-gdl/crates/gdl/src/dist/hop.rs:354), lines 360 and 421. With egress exhausted and `admission_wait` longer than the request deadline, an arriving forward request retains its admission share until that wait ends. No sender exists yet to receive downstream cancellation. Both entry handlers also wait for admission before checking expiration. This leaves review pass 2’s setup fix incomplete. **Change wanted:** reconstruct and validate the context first, then bound admission and egress acquisition by the request deadline. Add saturated-entry regressions.

3. **P2 — Stop forwarding starts after the dispatch acknowledgement.** [crates/gdl/src/dist/hop.rs:285](/home/ryan/repos/dynamo-gdl/crates/gdl/src/dist/hop.rs:285). If the remote sink starts but its forward acknowledgement is delayed, a caller’s stop remains unforwarded throughout `send_forward().await`; the stop loop begins only afterward. A sink awaiting stop can therefore remain blocked until the acknowledgement or setup timeout. **Change wanted:** forward stop through the outer anchor throughout provisioning and dispatch. Extend the pending-generation stop test with a delayed acknowledgement and require remote stop observation before it arrives.

4. **P2 — Decoding errors do not terminate the crossing stream.** [crates/gdl/src/dist/stages.rs:374](/home/ryan/repos/dynamo-gdl/crates/gdl/src/dist/stages.rs:374). `decode_stream` uses a plain `map`. If deserialization rejects one item, a backward node can read `Err(Codec)` followed by subsequent items; retaining that input also retains its upstream anchor. This violates terminal-error fusion at runtime boundaries. **Change wanted:** fuse decoded input at its first error and release upstream immediately. Test a decoder that rejects the first value but accepts the next, with a backward node that polls again after the error.

5. **P2 — Rendezvous reuses stale instances after restart.** [crates/gdl/src/dist/launch.rs:67](/home/ryan/repos/dynamo-gdl/crates/gdl/src/dist/launch.rs:67). Reusing the rendezvous directory loads previous processes’ peer files. Those files satisfy the expected-segment check before replacements publish and remain round-robin targets afterward, causing requests to dead instances. **Change wanted:** isolate membership by deployment generation, or enforce a fresh-directory contract. Test restarting into a directory containing previous-instance records.

6. **P3 — The spawned-task attribution is incorrect.** [agent-docs/perf/m3-remote.md:64](/home/ryan/repos/dynamo-gdl/agent-docs/perf/m3-remote.md:64). The direct baseline already spawns its producer at `benches/remote.rs:190`. Gdl additionally configures an unattached-anchor timeout, which velo implements with a spawned task; the direct baseline does not. The two extra tasks therefore cannot be attributed to “the producer’s pump and the outer end’s watcher.” **Change wanted:** correct the attribution to include the anchor timeout task.
