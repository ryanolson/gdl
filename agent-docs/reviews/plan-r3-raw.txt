New findings; velo paths are relative to the supplied checkout:

1. **Major — DEFER-TO-M3 — §7.2: activation must not depend on application output.** D returns a perpetually pending stream; E ignores its input and returns an empty stream. Local composition completes immediately; remote E never activates and eventually times out (`plan.md:142,157–158,167`). **Change:** activate through an explicit readiness signal after route setup and successful upstream stream establishment, independently of application data. Test pending upstream streams with input-ignoring and prefix-emitting backward nodes.

2. **Major — DEFER-TO-M3 — §7.5: source-drop churn defeats the memory proof.** With source admission one: D buffers output and finalizes; the client drops its source stream, freeing admission; delay remote cleanup; admit another root and repeat. Multiple completed egress slots remain despite one source permit (`plan.md:210–211,235`). Velo’s `finalize()` removes the sender registry entry before queued output necessarily drains, and its terminal can wait in a background task (`lib/velo/src/streaming/sender.rs:397–403,504–514`). **Change:** charge retained transport resources until confirmed retirement, or impose an aggregate egress quota with independently enforced expiry. Test successive roots with finished producers and delayed cleanup; anchor/task counts alone do not prove reclamation.

3. **Major — DEFER-TO-M3 — §§4, 7.5: one admitted root can allocate unbounded streams.** Concurrent attempts each mint anchors, while every entry sharing the root token bypasses another permit (`plan.md:85,209`). One root can retain N unpolled attempts, invalidating a bound based on fixed graph crossings (`plan.md:211`). **Change:** bound outstanding attempts/streams or charge their bytes separately. Include maximum frame sizes and both inlet and consumer buffers in the budget; velo has separate `C+1` buffers around its withheld queue (`docs/src/operations/saturation.md:105–113`). Test many simultaneous attempts under one root.

4. **Minor — DEFER-TO-M3 — §4: specify conservative skew conversion.** Rejecting near-expiry arrivals alone does not prevent late execution. A receiver 40 ms behind the source can accept early and schedule expiry 40 ms after the source deadline (`plan.md:80`). **Change:** define conversion explicitly, for example `mono_now + max(0, deadline_wall − wall_now − skew)`, with a stated pairwise clock-error assumption; alternatively document permitted late expiry. Test both offset directions. The distributed conversion can wait until M3; M1’s local monotonic deadline work can proceed.

5. **Minor — DEFER-TO-M3 — §7.2: direct run creation does not imply local attachment.** For backward segments `s2 → s1 → s3 → s1`, O is on `s1`, but the intermediate `s1` run writes to an anchor on `s3` (`plan.md:155–156`). Velo selects attachment locality from the handle’s worker (`lib/velo/src/streaming/anchor.rs:2429–2433`). **Change:** retain direct creation on O, then choose ordinary attach or ticket opening using the actual destination worker.

**Milestone 1 can start.** No finding blocks it. The type structure, codec representation, and local composition are sufficiently specified; the remaining protocol and resource-accounting corrections are M3 acceptance gates.
