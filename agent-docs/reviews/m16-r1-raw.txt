M16-CATALOG-01 (major) crates/gdl-extract/src/catalog.rs:126
Claim: Catalogue additions violate write-once semantics across instances and collide between threads.
Evidence: The existence check consults only self.entries, and rename at line 134 replaces an existing destination. A deterministic probe loaded two Catalog instances before either added race@1.0.0: the second add replaced the first entry's timestamp and file bytes. A separate barrier-synchronized 16-thread probe produced multiple ENOENT errors because every writer used the same version/PID temporary filename at line 132. These violate ruling 73 and the documented atomic publication guarantee.
Test idea: Keep a regression that loads two instances, adds different entries for the same key, and asserts that both return the first entry and preserve its bytes. Also synchronize independent instances in one process and require every add to succeed with one complete, parseable final entry. Publish uniquely named temporary files with atomic no-replace semantics and load the winning entry.
