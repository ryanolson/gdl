| # | Severity | Finding | Ruling | Evidence and fix |

| 1 | P1 | A producer blocked in `out.send` stopped watching its deadline and stop, and `finish_failed` blocked without a bound | valid | `a_producer_blocked_on_a_stalled_consumer_ends_at_the_deadline` uses a velo node with 4 credits and a 1 KiB slot budget, so backpressure is real. | 2 | P1 | Finished output was kept while the caller held an unread stream: the deadline timer ran only when the stream was polled | valid | `finished_output_is_released_at_the_deadline_while_the_stream_is_held`. | 3 | P1 | A request without a deadline could leave forward work that no cancel reaches | valid | `a_request_without_a_deadline_gets_the_runtime_default`. Fix: `RuntimeConfig::default_deadline` (600 s) is applied before any remote dispatch |
| 4 | P1 | `Open` was sent before `generate` succeeded, so a backward node that ignores its input could turn a failure into success | valid | `a_failing_generate_is_not_masked_by_input_ignoring_backward_nodes`. Fix: the inner end sends `Open` only after its node returns a stream; prepared runs forward the `Open` they receive instead of sending their own; the outer end waits for it before its backward nodes run. A setup failure is now the call's error, as in local composition. Three older tests asserted the error as a stream item and now assert it from the call |
| 5 | P1 | Early exits left the node context uncancelled, so helpers a node spawned outlived it | valid | `a_remote_node_context_is_cancelled_however_generate_ends` checks the published context itself on both the failing and the pending exit. The outer end gives local runs and the local inner end child scopes, so their end does not end the attempt |
| 6 | P1 | A stop was ignored while `generate` was pending | valid | `a_stop_reaches_a_remote_sink_whose_generate_is_still_pending` requires graceful completion, not a deadline failure. Fix: `produce_inner`, the prepared runs, and the outer end's wait for `Open` all forward stop while they wait |
| 7 | P2 | Two concurrent first entries of one root could reject each other in admission | valid | Unit test `concurrent_first_entries_of_one_root_share_the_permit_that_frees`: another root holds the only permit, two entries of one root wait, and the permit frees. Before the fix the second entry failed `Overloaded` after its 5 s wait. Fix: a waiting entry also wakes when any root is admitted and joins its own. A biased select keeps the uncontended path free of timers |
| 8 | P2 | The bench counted errors and truncated streams as items | valid | Every bench request now panics on an error, a short count, or a wrong item size, and the direct baseline requires `Finalized` |

The direct baseline also runs on velo's ticket path, which isolated the held memory as velo's own. `agent-docs/perf/m3-remote.md` is rewritten from the new numbers. The throughput gap at 16 KiB items is recorded as open, not attributed |
