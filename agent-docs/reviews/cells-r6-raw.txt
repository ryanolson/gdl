Reviewed `8c5caaa`. The revised eligibility, peer discovery, authentication, fail-stop behavior, and velo inventory resolve their corresponding round-five findings. Three major issues remain in §12.2.

1. **Major — Directory expiry bypasses the retention window.** [cells.md:453](agent-docs/cells.md:453) permits immediate closure when the record expires; the sequence then unregisters peers. A directory outage exceeding the 30-second lease can therefore interrupt healthy admitted streams despite a live, matching-epoch follow. This contradicts the discovery-only expiry rule at [cells.md:192](agent-docs/cells.md:192). Unregistering explicitly fails outstanding work: [fabric.rs:74](crates/gdl/src/dist/fabric.rs:74). **Change:** directory expiry must not close an authoritative live follow. Treat completed drain separately from directory withdrawal or loss, and retain transports until outstanding work has ended. Test directory expiry during a long stream over a healthy follow.

2. **Major — The deadline window assumes a maximum that gdl does not enforce.** [cells.md:453](agent-docs/cells.md:453) identifies `[runtime] deadline` as the longest admitted lifetime. The existing setting is `default_deadline_ms`, and it applies only when the caller supplied no deadline; longer explicit deadlines remain valid. Evidence: [runtime.rs:46](crates/gdl/src/dist/runtime.rs:46), [runtime.rs:156](crates/gdl/src/dist/runtime.rs:156), [hop.rs:352](crates/gdl/src/dist/hop.rs:352). Waiting the default can still cut a healthy request with a later deadline. **Change:** define and enforce a maximum cross-cell lifetime, including treatment of longer caller deadlines, or retain registrations through actual admitted completion/deadlines. Add a test whose explicit deadline exceeds the configured default.

3. **Major — The quiet period has no confirmed last-offer point.** The hub marks a cell not offered at [cells.md:451](agent-docs/cells.md:451), but the teardown sequence contains no acknowledgement that its instances applied that change. Membership updates run asynchronously: [fabric/hub.rs:544](crates/gdl/src/dist/fabric/hub.rs:544). Even with an enforced lifetime bound, a delayed chooser can offer another request after the hub starts its timer. When queued eligibility and drop updates subsequently arrive together, teardown can kill that still-active request. **Change:** collect reversible, generation-scoped acknowledgements after every relevant chooser applies exclusion, then start the retention window—or establish an equivalent last-offer bound. Cover joining/leaving choosers and pending selections. Test a request admitted through an old view while eligibility delivery is deliberately held.

**Verdict: REJECT.**
