VERDICT: REJECT

Source review only; no edits, builds, or tests. Velo paths below are relative to the supplied `velo-main` checkout.

1. **Blocker — §§6.2, 6.5: a legal placement requires serialization on a non-crossing response edge.** Place B/D/F/E together and C remotely. Only request edges cross, but the rule still mints B’s response anchor (`agent-docs/plan.md:119,152`). Same-worker velo attachment requires `Serialize`, and consumption requires `DeserializeOwned`; it still encodes msgpack (`lib/velo/src/streaming/anchor.rs:2389,802,817`; `streaming/sender.rs:326`). **Change:** specify a typed local continuation for forward excursions returning to the originating process, including instance affinity. Also type each backward-run anchor by that run’s input, before its local transforms.

2. **Blocker — §6.2: open-failure fallback races with successful attachment.** Interleaving: F/E attaches to `h_B`; its reply containing `h_F` is lost; D declares opening failed and attaches directly to `h_B`; velo rejects the second attachment. The promised error delivery fails (`agent-docs/plan.md:123,132`; `lib/velo/src/streaming/control.rs:479`; `streaming/anchor.rs:2380`). **Change:** define setup ownership, partial-success rollback, and exactly one terminal-error writer. Bound every backward-open and attach operation. Test a lost reply after the final anchor has been claimed.

3. **Major — §§4, 6.2–6.3: cancellation cannot reach remote forward work before backward setup.** Interleaving: remote C accepts and blocks; A drops its stream before D accepts; B’s unattached anchor is removed, but C receives no cancellation. Velo sends cancellation only when an attached sender identity exists (`agent-docs/plan.md:121,131,139`; `lib/velo/src/streaming/anchor.rs:496`). **Change:** establish cancellation ownership before running each remote forward stage, and propagate an execution/setup deadline. Ordinary remote stop/cancel is best-effort—the sends discard errors—so deadlines must independently bound abandoned work (`streaming/control/registry.rs:127,191`).

4. **Major — §§6.3, 6.5: premature EOF can be mistaken for success.** The plan maps explicit velo errors but does not require successful finalization (`agent-docs/plan.md:141,154`). Velo’s per-stream watchdog can lose its `Dropped` sentinel under saturation, leaving plain EOF (`lib/velo/src/streaming/control/pump.rs:350`; `streaming/anchor.rs:887`). Unattached timeout also removes the anchor without an error frame (`streaming/anchor.rs:1293`). **Change:** require an observed `Finalized` for successful completion; unexpected EOF becomes a terminal error. Specify handling of unexpected `Detached` and `SenderError` too.

5. **Major — §§6.2, 6.6: ticket and timeout rules omit material exceptions.** The direct-return rule permits tickets when producer and consumer share a worker, but `open_anchor_stream` rejects that case (`agent-docs/plan.md:133`; `lib/velo/src/streaming/anchor.rs:2263`). Prebinding pauses the configured unattached timeout and uses a separate 60-second window (`anchor.rs:1359`); successful opening means local staging, not receiver acceptance (`anchor.rs:2215`). Mux heartbeat detection takes 3–4 windows and suspends without data credit (`streaming/control/feed.rs:280`). **Change:** use ordinary attach for same-worker producers, distinguish absent tickets from failed opens, and specify independent setup/request deadlines. Correct the unconditional bounds at `agent-docs/plan.md:162,163`. Advance producer identity is not required to mint a ticket (`streaming/control/ticket.rs:17`).

6. **Major — §§3–5: attempt lifetime and cancellation scope are undefined.** `Next` is cloneable, reusable, and retainable; `Cx` merely mentions child tokens (`agent-docs/plan.md:64,77,98`). This leaves dropping one attempt, cancelling siblings, dropping a pending `generate`, and retaining `Next` after parent completion unspecified. **Change:** make each invocation own an attempt scope; parent cancellation propagates downward, while attempt cancellation preserves siblings and the operator’s ability to retry. State whether concurrent attempts are supported and what ordering they promise. Clarify ownership of `'static` returned streams: they cannot borrow `&self` or `&Cx`.

7. **Major — §§6.4, 8.4: service identity admits incompatible placements.** Discovery keys include graph/hash/segment, while the hash omits placement (`agent-docs/plan.md:148,204,247`). Moving C from `front` to `engine` without renaming segments lets a new front select an old engine that has no C handler. **Change:** include deployment and canonical routing/placement identity in discovery and admission. Define explicit schema-version discipline too; Rust type names cannot fingerprint changed serde representations.

8. **Major — §§5, 8.2–8.3: generated binaries have no implementation-construction contract.** Bindings provide types, but role traits provide no constructors; nevertheless the generator promises `start(config)` and runnable binaries (`agent-docs/plan.md:86,220,232`). **Change:** accept typed constructed bindings in the library and specify configurable factories for binaries. Prove this with a non-`Default`, asynchronously initialized node.

9. **Major — §§6.2, 10: bounded stream buffers do not bound accepted work.** Acceptance precedes concurrent producer execution, but there is no request-admission limit or aggregate memory budget (`agent-docs/plan.md:121,131,274`). Many slow consumers can retain one producer, route, and buffers per accepted request. **Change:** reserve bounded execution capacity before acknowledging; specify item/byte budgets and cancellation-aware pumps. Benchmark allocations, tasks, memory per concurrent request, throughput, and tail latency against direct calls and direct velo. Velo already allocates channels, registry entries, timeout tasks, and sender heartbeat tasks (`lib/velo/src/streaming/anchor.rs:1208`; `streaming/sender.rs:222`). Clarify that the map prohibition means no additional gdl correlation map.

10. **Major — §10: acceptance coverage does not prove arbitrary-placement execution or cleanup.** Enumerating partition results tests planning, while only two placements execute (`agent-docs/plan.md:273,274`). **Change:** add execution cases for forward-only excursions, local final backward transforms, repeated segment visits, multiple instances, and non-wire local types. Add observable tests for cancellation during forward/setup work, lost setup replies, unopened/expired tickets, saturated producer death, stop under backpressure, and dropping pending generation. Assert anchors, senders, and owned tasks return to baseline. A graceful node shutdown alone does not prove crash detection. Move the concrete wire-probe feasibility test ahead of the full runtime milestone.

11. **Minor — §§3, 5, 8.4: two declared contracts need explicit enforcement.** `Items<T>` permits `Err` followed by more items despite terminal-only errors (`agent-docs/plan.md:63,84`); validation requires every node’s binding despite sources having no implementation (`:56,246`). **Change:** identify the boundary that terminates and releases a stream after its first error; exempt sources from binding requirements.

Section 12 rulings:

1. **AGREE: direct velo behind one internal module.** Existing attachment, ticket, cancellation, mux-lane, and simulation facilities support this choice; the missing work is graph lifecycle policy, not a public transport trait (`lib/velo/src/lib.rs:1120,1179`; `streaming/anchor.rs:2396`; `simulation.rs:4`).
2. **Provision the backward route before producer work starts**, with bounded setup, explicit ownership transfer, and partial-failure cleanup; separately connect cancellation to forward stages.
3. **Keep terminal-only infrastructure errors**, enforced at runtime boundaries; recoverable application errors remain payloads.
4. **Keep `graph!` plus manifest dump.** Concrete autoref probing is workable in principle inside the expansion, but a generic helper loses that property; retain generated serde-bound assertions and test aliases, concrete generics, serialize-only, borrowed-deserialize, and non-wire types.
5. **Start with an explicit instance/peer roster**, retaining the discovery seam; velo supports manual peer registration, while service discovery adds backend and registration-guard ownership (`docs/src/concepts/discovery.md:21,30,32`).
6. **Acknowledge bounded acceptance**, after validation, capacity reservation, and cleanup ownership are established; do not use fire-and-forget.
