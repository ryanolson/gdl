1. **P2 — Retain admission when a hand-off fails.** [crates/gdl/src/dist/hop.rs:407](/home/ryan/repos/dynamo-gdl/crates/gdl/src/dist/hop.rs:407) drops the admission share even when `send_forward` returns an error. This stage still owns the reply and subsequently awaits failure delivery, potentially spending another setup timeout attaching. Repeated downstream refusals can therefore accumulate unaccounted tasks despite the admission limit. Release the share immediately only after successful acknowledgement; otherwise retain it until `fail` completes. Add a regression that stalls failure delivery and verifies admission remains occupied.

2. **P2 — Reject heartbeat intervals that become zero on the wire.** [crates/gdl/src/dist/runtime.rs:183](/home/ryan/repos/dynamo-gdl/crates/gdl/src/dist/runtime.rs:183) rejects only `Duration::ZERO`, so the public Rust configuration accepts `Duration::from_micros(500)`. Velo truncates this through `as_millis()` when constructing its ticket, then reconstructs a zero interval for the sender’s Tokio heartbeat timer, which panics. Reject intervals below one millisecond before deployment and add a test using a nonzero submillisecond duration.
