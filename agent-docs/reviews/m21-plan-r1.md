# Milestone 21, metrics per node: plan review round 1

Reviewer: a fresh Fable subagent, read-only. It reviewed the first draft of the milestone 21 addendum (rulings 124 to 130 and the stages) against rulings 102, 104, 116 to 118, and 123, `agent-docs/dynamo.md`, `agent-docs/perf/benchmarking.md`, dynamo's metrics code at `70e584a276`, prometheus 0.14's registry, and the runtime's stages, hops, process, and generated segments. Stage 1 was being written alongside, uncommitted; the reviewer cited it where it showed how a ruling was realized. Verdict: APPROVE WITH CHANGES, 2 must change, 5 should change, 6 nits. Every finding is taken into the addendum.

| # | Finding | Taken as |
|---|---|---|
| M1 | "attached by `DHop::new`, by path position" would meter every hop's outer end; for a nested hop that is the operator, whose every call to `next` runs `DHop::generate`, so operators would be counted once per attempt on top of their own call | ruling 128: only the hop whose outer end is the source meters it; ruling 130 adds an operator that calls `next` twice, and a backward node and the source counted once |
| M2 | every bench row listed runs one request at a time, so the atomics are never contended and "nothing beyond the spread" proves nothing about the risk the pre-measurement named | ruling 129: a `concurrent/reference-1-segment` row, 32 requests in flight, metrics off and on, is the row the 5% gate reads; `reference-1-segment` was already added in `95ea739` |
| S1 | a consumer that stops at the first error item drops the stream, so "dropped before it ended" would count a failing sink read locally as a cancellation; a drop at the deadline is not a cancel either | ruling 128: the first of end, error, or drop decides; a drop after the deadline is `deadline_exceeded`; both cases in 130 |
| S2 | "the words `counter`, `gauge`, `size`, `time` anywhere but first" refuses dynamo's own `worker_last_time_to_first_token_seconds` and `model_kv_cache_block_size`; dynamo forbids them as suffixes; Prometheus's `_sum`, `_count`, `_bucket` suffixes are not refused | ruling 125: refused only at the unit position, with `sum`, `count`, and `bucket` added; the `_seconds` rule, stricter than dynamo's `_ms`, goes into `LIMITATIONS.md` |
| S3 | the early velo bind changes the lifecycle: discovery and `bind_container_node` move into `Process::start`, test call sites bind a node each, a stop while loading drops a bound node; adding `worker_id` at scrape time would avoid it | ruling 127 keeps the bind and says why (a metric a node defines would otherwise gain a second series after a load that may take minutes); the listener binds first, and `run_segment` reads the deployment before it builds |
| S4 | 130 lacks: operator and backward nodes; an error then a drop; a deadline drop; a forward node dropped mid-`forward`; a stream held unread; a refusal at admission | ruling 130 adds each but the forward node dropped mid-`forward`, which the drop case of a forward node's meter covers in the same code path |
| S5 | every sink and backward stream gains a wrapper polled per item, and 129 had no per-item row | ruling 129: `reference-items/2-segments` with metrics on, the per-item control |
| N1 | `uptime_seconds` is in 127, not 128 | ruling 125 cites both |
| N2 | velo's instance id is a UUID; dynamo's `worker_id` a u64 in hex | ruling 127: the UUID's simple form; both opaque to relabelling |
| N3 | prometheus refuses an empty prefix; common labels come out in a hash map's order | ruling 127: empty maps to no prefix; tests parse the text |
| N4 | frontends and services gain `type Metrics`; the generated builder names a frontend by the source and an adapter by its entry | rulings 124 and 127 say so |
| N5 | `error_type`'s values differ from dynamo's | ruling 128, and `LIMITATIONS.md` in stage 5 |

Checked and sound by the reviewer: prometheus 0.14 applies a registry's prefix and common labels only in `gather`, refuses a second help text or label set with a message naming neither node, accepts per-node const labels, and checks neither kind nor buckets, which the `Builder`'s check closes; dynamo's prefix, identity labels, the five names, the buckets, and `uptime_seconds` all match; no double counting on any other path (each forward and backward position and the inner end is called once per attempt; relays and local short cuts add no second call); an interrupted request that never calls a node is not counted for it; `RuntimeConfig` as the carrier, after `faults`; the seal, the shared parser, `MetricField`'s omitted empty fields, and `--verify`; every velo call stays in `dist::fabric`.
