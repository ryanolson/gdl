1. **P1 — Blocked sends disable deadline enforcement.** [crates/gdl/src/dist/hop.rs:543](/home/ryan/repos/dynamo-gdl/crates/gdl/src/dist/hop.rs:543). Once `pump` awaits `out.send`, it stops polling `cx.done()` and graceful stop. Velo’s `streaming/sender.rs:326` waits only for capacity or cancellation. A stalled consumer can therefore retain the producer task, admission share, and egress permit indefinitely past the deadline. `finish_failed` repeats the unbounded send at line 556. Keep interruption handling active throughout sends and bound failure delivery. Test with an observably saturated queue; the current eight-item stop test never establishes backpressure.

2. **P1 — Finished output does not expire when the consumer stops polling.** [crates/gdl/src/dist/fabric.rs:90](/home/ryan/repos/dynamo-gdl/crates/gdl/src/dist/fabric.rs:90). A producer can fill the credit window, queue additional output, finalize, and release its egress permit while the caller retains an unpolled response stream. Its deadline timer runs only through stream polling; `mint` installs no independent deadline cancellation. Velo’s `peer_batcher/records.rs:288` confirms that the terminal waits behind withheld items, and its watchdog exempts streams without credit. Successive roots can accumulate retained output indefinitely, contradicting ruling 15’s deadline guarantee. Retire anchors independently of consumer polling and test retained bytes after finished producers’ deadlines.

3. **P1 — Requests without deadlines can leak uncancellable forward work.** [crates/gdl/src/dist/envelope.rs:50](/home/ryan/repos/dynamo-gdl/crates/gdl/src/dist/envelope.rs:50). `Cx::new()` crosses segments with no deadline, and the runtime supplies none. If a remote forward transform stays pending, dropping the caller’s stream cannot cancel it: that stage has not attached a response anchor, and its fresh context’s `done()` never resolves. Its task and admission share remain live indefinitely. Require or supply a finite deadline before remote dispatch, preserve it across hops, and test caller abandonment during a pending remote transform.

4. **P1 — Premature activation can turn a setup failure into success.** [crates/gdl/src/dist/hop.rs:473](/home/ryan/repos/dynamo-gdl/crates/gdl/src/dist/hop.rs:473). `Open` is sent before `inner.call` succeeds. A prepared backward node that ignores its input can consume that signal, return successfully, and discard the sink’s subsequent `generate -> Err`. Local execution returns that error before invoking any backward node. The outer backward run also activates without waiting for `Open` at line 283. Gate backward-node activation on successful upstream stream establishment, including the outer run; deliver preceding failures directly. Add local-versus-remote tests combining a failing `generate` with input-ignoring backward nodes.

5. **P1 — Early generation exits leave node contexts uncancelled.** [crates/gdl/src/dist/hop.rs:483](/home/ryan/repos/dynamo-gdl/crates/gdl/src/dist/hop.rs:483). A remote sink can spawn a helper waiting on its supplied context’s cancellation, then return `Err` or remain pending until the deadline. Both exits occur before `fuse` installs its cancellation guard. Dropping the fresh remote context does not cancel surviving clones, so the helper outlives response retirement. Install cancellation ownership before invoking the node and retain it through successful stream retirement. Test the published node context’s cancellation on both exits, rather than only checking that the generation future was dropped.

6. **P1 — Graceful stop is ignored while `generate` is pending.** [crates/gdl/src/dist/hop.rs:484](/home/ryan/repos/dynamo-gdl/crates/gdl/src/dist/hop.rs:484). A sink or operator awaiting `cx.stopping()` before returning buffered output never receives a remote stop: `produce_inner` watches cancellation and deadline, while stop forwarding begins only in `pump`. Velo exposes and retains stop separately from cancellation, so this is a runtime propagation gap. Forward stop while preserving the pending generation future. Add a setup-phase stop test that requires graceful completion instead of deadline failure.

7. **P2 — Concurrent entries of one root can reject each other.** [crates/gdl/src/dist/admission.rs:49](/home/ryan/repos/dynamo-gdl/crates/gdl/src/dist/admission.rs:49). With limit one, two concurrent first entries can both miss `join(root)`. One acquires the permit and inserts the root; the other waits exclusively for another semaphore permit and returns `Overloaded` while the first remains active. The occupied-entry check cannot help until another permit becomes available. Coordinate pending admission per root or wake and recheck membership during the wait. Add a deterministic test forcing both initial lookups before either insertion.

8. **P2 — Benchmark failures are counted as performance improvements.** [crates/gdl/benches/remote.rs:140](/home/ryan/repos/dynamo-gdl/crates/gdl/benches/remote.rs:140). `through` discards errors; the direct baseline treats every non-item frame as completion at line 123. Neither validates the returned count, while Criterion credits 1,000 items per iteration. A stream truncated after one item therefore produces a misleading throughput result. Reject every error, require the requested item count, and require explicit `Finalized` from the direct baseline.

9. **P2 — The performance comparison does not isolate the claimed overhead.** [agent-docs/perf/m3-remote.md:16](/home/ryan/repos/dynamo-gdl/agent-docs/perf/m3-remote.md:16). The attributed “13%” overhead compares an instrumented graph—including task/channel work, event logging, and multiple string transformations—with a direct sender formatting one string. The shared event log also grows throughout benchmarking. No resident-memory measurement or isolated crossing-copy measurement satisfies the milestone’s measurement gate. Use matched workloads with bounded instrumentation, measure tasks created per request and resident memory, isolate copy cost across payload sizes, and revise the attribution.
