| 1 | P1 | `Open` was sent with a plain `send`, which waits without watching the deadline or stop | partially valid | Reachable only if the transport stalls: velo's heartbeat task `try_send`s into the same bounded channel as items (`streaming/sender.rs:239-243`), so a stalled transport can fill it before `Open`. Every consumer in gdl reads while it waits for `Open`, so a stalled reader cannot cause it. No deterministic test reaches a transport stall; a fault hook that blocks the send would be tautological. Fix: `Open` goes through `deliver`, the interruption-aware send every item already uses |
| 2 | P1 | An arriving hand-off or open took its admission share before checking expiry, then waited for egress without the deadline, holding the share | valid | `an_entry_waiting_for_egress_does_not_hold_its_share_past_the_deadline`: egress limit 1, held by an endless stream; a 3 s wait and a 300 ms deadline. | 3 | P2 | Stop was not forwarded while the outer end waited for a delayed hand-off acknowledgement | valid | `a_stop_reaches_the_remote_sink_while_its_hand_off_is_unacknowledged`: with a 3 s delayed ack, the sink never saw the stop within 1 s. | 4 | P2 | A crossing's decoded input continued after a decode error, and kept its upstream anchor | valid | Unit test `decoding_ends_at_the_first_error_and_releases_its_input` (an invalid msgpack byte, then a valid item): before the fix, the input survived the error. Corrected: the extra tasks are the watcher and that timer |
