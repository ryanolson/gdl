# Milestone 23, routing selectors: implementation review

Reviewer: Codex (`codex:codex-rescue`), read-only, adversarial. It reviewed `d810618..b405987` (the model, the runtime, the segment binary, the composer, and the bench) against rulings 152 to 165 and the owner's constraints. Each finding was checked with a test before any change. The reviewer re-traced the lease on the error, stream-drop, hedge, relay, and local self-instance paths, and found no leak.

| # | Finding | Ruling | Taken as |
|---|---|---|---|
| M1 | `LeastLoaded` prunes idle counts that are not in the current view (`least.rs:48`). One selector serves every crossing that names it, into any segment, so a view of one segment drops another's counts: a concurrent pick of that segment can reload a table without its instances and panic at the scan, or add to a count that was just dropped, which later picks no longer see | valid. Test `a_view_of_one_segment_keeps_every_count_of_another` failed: an idle count was replaced after a pick into another segment | counts are only ever added, never dropped or replaced, so the table loaded after the update holds every instance asked for and a loaded count stays the one later picks read. The cost is an entry of a few dozen bytes per instance this sender has ever routed to; said in the type's doc |
| M2 | `LeastLoaded` binary-searches the new table while it still appends unsorted (`least.rs:54`), so an instance already counted can get a second count when a new instance sorts before it | valid. Test `a_new_instance_never_doubles_the_count_of_a_known_one` failed with two counts for one instance | each new instance is inserted at its sorted position |
| S1 | a request cancelled inside its selector is still dispatched: `send_forward` does not check the context after the selector returns (`runtime.rs:509`) | invalid as stated. Test `a_request_cancelled_while_its_selector_chose_is_not_handed_on` passed 20 of 20 without a change: the hand-off's enclosing select is biased to the request's end and drops the hand-off at its next await, so nothing reaches the receiver, the request fails `Cancelled`, and the lease is given back | no change; the test stays |
| S2 | a valid name with `__` or a trailing `_` cannot be reached from the environment: `GDL_SELECTOR__FOO__BAR__KEY` splits at every `__` (`process.rs:1163`) | valid; a judgment call on severity, since a settings file still works | a selector name is now words joined by single `_`s, so `foo__bar` and `foo_` are refused (ruling 155 amended in the as-built note). Test cases added to `a_selector_name_must_be_one_a_placement_can_use` |

No must-fix touched the routing table, `pick`, or membership: M1 and M2 are in a reference selector's own state. So no second pass was run.

**Addendum (2026-10-22, review `split-r5`): S1 is valid.** The test passed 20 of 20 on an idle host. With the whole `selectors` target run under twice as many busy processes as cores, it failed 7 of 80: the engine counted a forward. The enclosing select sees the request's end only at its next await, and the send could leave before it. `send_forward` now checks the context after the selector returns (`runtime.rs`). Under the same load, the test then failed 0 of 80.
