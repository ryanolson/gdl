New findings; velo paths are relative to the supplied checkout:

1. **Major — §6: one concrete `Absent` cannot implement different port types.** F requires `Backward<In=Raw, Out=Tok>`; E requires `Backward<In=Tok, Out=Out>`. One `Absent` cannot supply both associated-type assignments (`plan.md:129,251–252`). **Change:** use `Absent<NodeMarker>` or a marker-parameterized slot dispatcher. This does let binaries avoid naming unhosted implementation types. Prove it in milestone 1 with differently typed absent nodes.

2. **Major — §6: runtime codec presence does not establish Rust trait bounds.** Checking `Option<Codec<T>>` cannot make generic `T` satisfy velo’s `Serialize`/`DeserializeOwned` requirements (`plan.md:130–131`; `lib/velo/src/streaming/anchor.rs:802,2389`). **Change:** specify monomorphized wire factories/operations carried by the capability, or an explicitly byte-based transport representation. Extend the early spike to compile the same generic dispatcher with local non-serde types and remote serde types; probe classification alone proves neither integration nor the claimed dispatch costs (`plan.md:328`).

3. **Major — §7.2: backward completion races provisioning.** E legally returns an empty stream and drops its input. O provisions E; E’s pump finalizes `anchor_k` and removes `anchor_E`; O then provisions F against `h_E`; attachment fails and setup returns an error instead of local execution’s empty success (`plan.md:104,148–151,172`; velo `streaming/anchor.rs:793,2438`). **Change:** separate preparation from activation, or explicitly propagate early completion and short-circuit remaining setup. Test empty and immediately failing backward streams with multiple intermediate runs.

4. **Major — §§4, 7.4: remaining-time propagation renews expired work.** O sends a one-second budget; delivery waits five seconds; the receiver reconstructs `now + 1s` and starts work after O expired. Every delayed hop can extend the deadline again (`plan.md:75,173,190,194`). Dropping the unary result does not reliably withdraw delivery (`lib/velo/src/messenger/client/builders/results.rs:54–59`). **Change:** specify an end-to-end deadline protocol with explicit clock/skew assumptions, or weaken the guarantee to receiver-local budgets. Test delivery after the original deadline.

5. **Major — §7.5: one request can exhaust its own admission capacity.** With placement `{A,B,D,G}/{C,F,E}` and capacity one on the second segment, provisioning F/E consumes its permit while waiting for D. C then cannot enter, although D cannot start until C finishes (`plan.md:148–155,198–199`). **Change:** distinguish run reservations from request admission and define reentrant capacity handling. Either share an attempt-scoped reservation or validate sufficient route capacity. Test this exact placement at capacity one.

6. **Major — §7.5: producer completion does not retire buffered transport resources.** Velo’s synchronous `finalize()` can leave its terminal queued in a background task (`lib/velo/src/streaming/sender.rs:397–403,509`). Releasing admission when producer work ends allows successive requests while stalled consumers retain earlier streams. The stated budget also omits the default 1 MiB per-slot withheld queue and separate `C+1` inlet/consumer buffers (`plan.md:199–200`; velo `docs/src/operations/saturation.md:105–125`). **Change:** define resource reservations through retirement/cancellation, account for byte limits, and test repeated short producers with unpolled consumers. Add resident-memory measurement; milestone 3 currently lists only latency, allocations, and tasks (`plan.md:330`).

7. **Minor — §7.2: intermediate runs can revisit O’s segment.** Backward placement `D@s2 → F@s1 → E@s3 → B@s1` has an intermediate run in O’s segment, contradicting “each in another segment” (`plan.md:148`). **Change:** provision every intermediate run, including local revisits; specify the local opening path rather than assuming self-addressed unary works.

8. **Minor — §7.3: ticket failure is not confined to the first send.** Opening can fail immediately; rejection can cancel the sender before its first item; locally accepted sends may precede receiver rejection (`plan.md:181`; velo `streaming/anchor.rs:2215–2231`). **Change:** say “immediate open error or later sender cancellation/send failure,” and watch cancellation while generating the first item.

9. **Minor — §11: two acceptance assertions contradict the design; exhaustive scope needs precision.** A lost forward ack can yield **success** when downstream wins attachment and finalizes before the upstream timeout (`plan.md:170–171,330`). Remote forward cancellation is explicitly deadline-only (`plan.md:194,330`). **Change:** assert exactly one completion and cleanup for lost acknowledgments, and deadline-bounded release for remote forward work. Define exhaustive placement testing as the **877 canonical partitions of seven nodes**: feasible with one fully bound mock build and at most seven simultaneous workers; rebuilding workers per case costs **3,263 segment starts**. Keep fault tests separate from that exhaustive happy-path matrix, and move the `Absent`/codec integration spike before milestone 3.
