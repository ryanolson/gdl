# Milestone 23, routing selectors: plan review

Reviewer: Codex (`codex:codex-rescue`), read-only, adversarial. It reviewed the first draft of the 2026-10-21 addendum (rulings 152 to 165) against the runtime (`dist/roster.rs`, `dist/runtime.rs`, `dist/hop.rs`, `dist/stages.rs`, `wire.rs`, `binary.rs`, `process.rs`), the placement model, and the composer. Each finding was checked against the code. No finding is a claim about behavior that exists today, so none has a failing test yet; the tests that prove each change are in ruling 164.

| # | Finding | Ruling | Taken as |
|---|---|---|---|
| M1 | ruling 154 said an acknowledged instance is never sent to after its acknowledgement; another thread can acknowledge between the check and the send (`roster.rs:113`, `roster.rs:290`, `runtime.rs:451`), which ruling 150 already allows for `pick` | partially valid. The defect is in the wording, not the mechanism: the same window exists between `pick` and its send, and rulings 112 and 150 cover it. The check after a selector returns does what `pick` does, and nothing waits after it but the encoding | ruling 154 restated: the check is the selection's pick, under the grace and the close as `pick` is. No hook test: the window is `pick`'s, which milestone 22's close test covers |
| M2 | a 5% whole-request gate can accept a measurable dispatch cost; the reference rows never use `random`; a larger future cost this path 8,000 instructions before (`hop.rs:309`) | partially valid. The 5% gate is the owner's and stays. A `random` row is missing, and the future size is not reported | ruling 165: a two-segment `random` setup and the root hop's future size are added to the bench in a commit before the change, so that the base binary has them; any built-in row beyond its spread is reported to the owner |
| S1 | correct output from the placement matrix does not prove the lease's lifetime: it holds whether a lease drops at once or at the end (`hop.rs:548`, `:588`, `:764`, `runtime.rs:454`) | valid | ruling 164: a counting selector shows each drop (outer end open and closed, a failure before the open signal, a hedging operator's attempts, a relay with its input open and ended, a hand-on at the acknowledgement); the matrices count leases taken against hand-offs and require none live once settled |
| S2 | the head type of a streamed edge is `H`, not the codec's `Streamed<H, T>`; the typed tests miss it and the `Absent` slot (`wire.rs:67`, `:142`, `stages.rs:115`) | valid | ruling 153: `RequestCodec` reports its head type by position, as `streamed`; ruling 164 tests `H` accepted, `Streamed<H, T>` and `T` refused, with the destination slot `Absent` |
| S3 | "any value" as a lease cannot enter the response holder, which needs `Send + 'static` (`hop.rs:1454`) | valid as a specification gap | ruling 157: `with_lease<L: Send + 'static>`, taken out of the choice before the snapshot is released |

Left for the owner, not blocking: ruling 162 defers the generator's binding of selector crates to the KV-router milestone; until then a selector from another crate needs a hand-written `SegmentBinary` or an in-process deployment.
