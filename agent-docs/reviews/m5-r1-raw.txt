1. **[P1] Readiness does not cover every routable instance** — [crates/gdl-gen/src/emit.rs:522](/home/ryan/repos/dynamo-gdl/crates/gdl-gen/src/emit.rs:522). The first rendezvous can collect two engine instances, but the readiness rendezvous succeeds when only one is ready. Round robin can then send requests to the other instance before its handlers exist—or after its startup failed. Require readiness for every instance in the routing roster. Add a regression test that pauses one replica between publication and handler registration.

2. **[P2] Zero heartbeat intervals survive startup validation** — [crates/gdl/src/dist/runtime.rs:139](/home/ryan/repos/dynamo-gdl/crates/gdl/src/dist/runtime.rs:139). `heartbeat_interval_ms = 0` deserializes successfully and reaches velo’s `tokio::time::interval_at`, which panics for a zero period when a stream attaches. Reject zero during configuration validation, before publishing the instance, with an error naming the setting.

3. **[P2] Response serialization can panic the source process** — [crates/gdl-gen/src/emit.rs:612](/home/ryan/repos/dynamo-gdl/crates/gdl-gen/src/emit.rs:612). Serde/MessagePack capability does not guarantee JSON compatibility: a response containing a map with tuple keys is one counterexample. `json!` internally unwraps serialization failures, terminating the frontend instead of emitting the promised terminal error. Use fallible serialization, cancel the affected stream, and test that the driver answers a subsequent request.

4. **[P2] Generation depends on the caller’s formatter configuration** — [crates/gdl-gen/src/emit.rs:76](/home/ryan/repos/dynamo-gdl/crates/gdl-gen/src/emit.rs:76). Rustfmt inherits the working directory and discovers its configuration there. Formatting the same generated frontend source from two existing directories produced different bytes. Consequently, unchanged inputs can fail `--check` depending on invocation location. Explicitly control formatter configuration and toolchain, and test generation from directories with conflicting rustfmt settings.

5. **[P2] `--check` misses executable output drift** — [crates/gdl-gen/src/lib.rs:175](/home/ryan/repos/dynamo-gdl/crates/gdl-gen/src/lib.rs:175). Unexpected files are inspected only when their first line contains the marker. Adding an unmarked `front/build.rs` changes Cargo’s behavior while passing the check. The unconditional `target` exclusion also hides stale output for a valid segment named `target`. Check unexpected Cargo inputs independently of markers and distinguish build directories from segment directories. Exercise these cases through the actual CLI.

6. **[P2] Distinct segment names collapse to the same package** — [crates/gdl-gen/src/emit.rs:102](/home/ryan/repos/dynamo-gdl/crates/gdl-gen/src/emit.rs:102). Names such as `worker-a` and `worker_a`, or `Engine` and `engine`, pass validation but produce identical package and binary names. The resulting crates cannot coexist in the example’s workspace and can overwrite the same binary artifact when built separately. Validate uniqueness and legality of emitted package/library names before rendering, reporting both conflicting segments.

7. **[P2] Conflicting binding paths are silently discarded** — [crates/gdl-gen/src/emit.rs:230](/home/ryan/repos/dynamo-gdl/crates/gdl-gen/src/emit.rs:230). When two hosted bindings name the same package at different paths, insertion into `implementations` silently keeps the last path. Both nodes then use that dependency, potentially compiling successfully against an unintended implementation. Validate dependency identity before emission: repeated package names must resolve to the same source, and binding manifests must match their declared package names.

8. **[P2] Concurrent generations can inspect the wrong contract** — [crates/gdl-gen/src/dump.rs:18](/home/ryan/repos/dynamo-gdl/crates/gdl-gen/src/dump.rs:18). Dump sources are shared by target directory and package name. Two worktrees with the same contract package can overwrite each other’s manifest or `main.rs` before Cargo reads them; Cargo’s build lock does not protect these preceding writes. Use a private source directory per invocation while sharing only the compilation cache.
