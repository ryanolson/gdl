1. **P1 — Cancellation disables deadline cleanup without cancelling the anchor.** [crates/gdl/src/dist/hop.rs:254](/home/ryan/repos/dynamo-gdl/crates/gdl/src/dist/hop.rs:254): After `call` returns, cancel the original `Cx` while retaining the unread response. The watcher exits without calling `watcher.cancel()`, and the stream’s cancellation handling requires polling. The anchor can therefore survive even past its deadline. Stop propagation similarly depends on polling `InboundItems`. **Change wanted:** forward cancel and stop independently of response polling; cancel the anchor before the watcher exits. Add regressions that retain the unread stream while observing remote cancellation and stop.

2. **P1 — Deadline cleanup still retains unread response bytes.** [crates/gdl/src/dist/hop.rs:253](/home/ryan/repos/dynamo-gdl/crates/gdl/src/dist/hop.rs:253): Reading `Open` installs velo’s receive-feed clones inside `StreamAnchor`. `StreamController::cancel()` removes the registry entry and closes the slot, but those clones—and their queued frames—remain until the anchor is polled again or dropped. Thus the watcher releases the registry entry without releasing all buffered output. The regression at `tests/faults.rs:768` checks only `active_anchors()`, so it misses this incomplete fix to prior finding 2. **Change wanted:** make deadline expiry release the actual receive buffers independently of caller polling, through runtime ownership changes or an appropriate velo API. Test retained bytes while the response remains held.

3. **P1 — Detached remote setup work can outlive the request deadline.** [crates/gdl/src/dist/hop.rs:391](/home/ryan/repos/dynamo-gdl/crates/gdl/src/dist/hop.rs:391): After a remote forward transform completes, the onward `send_forward().await` no longer selects on `cx.done()`. A delayed acknowledgement retains its task, context, and admission share until `setup_timeout`, even after the request expires. `open_run` and `run_inner` likewise await admission/egress or attachment without the request deadline bounding those waits. Cancelling the outer anchor cannot interrupt a forward stage that has no attached sender. **Change wanted:** enforce the earlier of request deadline and setup timeout throughout remote setup and handoff, including failure attachment. Add a delayed-ack regression that checks remote resource retirement at the deadline.

4. **P2 — A zero attempt limit leaks one ledger entry per rejected root.** [crates/gdl/src/dist/admission.rs:111](/home/ryan/repos/dynamo-gdl/crates/gdl/src/dist/admission.rs:111): With `RuntimeConfig::attempt_limit = 0`, `or_insert(0)` creates an entry before rejecting the attempt. No `AttemptSlot` exists to remove it, so repeated rejected requests grow the map indefinitely and leave `attempting()` nonzero. **Change wanted:** reject zero during configuration validation or reject attempts without inserting an entry. Test repeated distinct roots with a zero limit.

5. **P2 — The performance attribution still compares different opening protocols.** [crates/gdl/benches/remote.rs:259](/home/ryan/repos/dynamo-gdl/crates/gdl/benches/remote.rs:259): Latency, throughput, allocation, and spawned-task measurements always use `direct_open(..., false)`, while gdl uses tickets. The ticket baseline runs only in the held-memory experiment. Consequently, the claim at `agent-docs/perf/m3-remote.md:63` that the difference isolates one task and 15 allocations of gdl overhead is unsupported; it also includes differences between attach and ticket setup. **Change wanted:** measure the ticket baseline for every attributed metric and update the conclusions from those matched results.
